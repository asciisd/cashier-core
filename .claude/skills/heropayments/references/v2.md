# V2 Flow

## Common

### Rates

`GET https://api.heropayments.io/v2/rate?currencyFrom=usd&currencyTo=sol&transactionType=deposit`

This method allows you to get crypto to crypto or fiat to crypto exchange rate.

- currencyFrom - fiat or cryptocurrency;

- currencyTo - cryptocurrency;

- transactionType - always deposit or withdrawal.

Response fields:

- rate - shows an amount of currencyTo per 1 currencyFrom;

- reverseRate - shows an amount of currencyFrom per 1 currencyTo.

Get available crypto and fiat currencies by using the method [GET "Supported currencies"](https://documenter.getpostman.com/view/17469357/UVyvwv7a#699875a1-914c-4a63-ae69-204f7ab5626d).

#### Exchange rate — 200 OK

```json
{
    "currencyFrom": "usd",
    "currencyTo": "sol",
    "transactionType": "deposit",
    "rate": "0.009344788065158223162995988",
    "reverseRate": "107.4502406750799836205991875"
}
```

### Supported currencies

`GET https://api.heropayments.io/v2/currencies`

By using this method, you can see the list of supported cryptocurrencies.

You can also set `?fiat=true` to get the list of supported fiat currencies.

**ticker -** shortened name of the currency\
**fullName -** name of the currency\
**extraIdName -** extra id of the currency, if it has one\
**isStable -** shows if the currency is a stablecoin or not\
**confirmations -** shows the number of confirmation blocks of the currency\
**blockchain -** shows the blockchain currency is operated on\
**image -** svg icon of the currency

### Minimum payment amount (V2)

`GET https://api.heropayments.io/v2/min-amount?currency=eth`

To retrieve minimum amounts for all supported cryptocurrencies in bulk, call `v2/min-amount`.

To get the minimum amount for a specific cryptocurrency, use the currency query parameter, for example: `?currency=btc`.

To retrieve minimum amounts for all cryptocurrencies estimated in fiat, call\
`v2/min-amount?baseCurrency=usd`.

Response fields:

- `minDeposit` — minimum amount required for a deposit transaction

- `minWithdrawal` — minimum amount required to create a withdrawal transaction

- `currency` — cryptocurrency

- `baseCurrency` — fiat currency

The list of supported cryptocurrencies and fiat currencies can be obtained via the [GET "Supported currencies"](https://documenter.getpostman.com/view/17469357/UVyvwv7a#699875a1-914c-4a63-ae69-204f7ab5626d).

#### Get the minimum payment amount — 200 OK

```json
{
    "minDeposit": 0.07679,
    "minWithdrawal": 0.07679,
    "currency": "eth"
}
```

### Payment status check by id (V2)

`GET https://api.heropayments.io/v2/payments/:id`

To get information about the status of a deposit/withdrawal, you need to provide a payment ID.

*NOTE!* [GET "Payment status check by id (V2)"](https://documenter.getpostman.com/view/17469357/UVyvwv7a#f850d90d-7926-46f6-bcbf-4b90369cbbf8) *request should be made with the same API key that you used to create a deposit/withdrawal"request.*

Possible statuses:

- **waiting** - the initial status of each deposit and withdrawal. Waiting for a transaction to appear in a blockchain;

- **confirming** - waiting for confirmations in a blockchain. There is a minimum required amount of confirmations to consider a crypto transaction finished;

- **exchanging** - crypto exchange process. In case of deposits: from a client's payCurrency to the merchant's balance currency. In case of withdrawals: from the merchant's balance currency to the client's payoutCurrency;

- **sending** - crypto is on its way to the merchant’s wallet (deposit scenario) or the user’s wallet (withdrawal scenario). Considered as a "success" status for deposits only;

- **finished** - the transaction is processed successfully. Considered as a "success" status;

- **failed** - the transaction is failed due to an error;

- **refunded** - the funds were refunded back to the user’s/Merchant’s wallet;

- **hold** - the transaction is marked as suspicious and the user must pass KYC procedure;

- **expired** - the user didn't send the funds to the specified address in the 4 hour time window, and the created payment expired.

More information could be found in [Payments statuses - (V2 flow)](https://documenter.getpostman.com/view/17469357/UVyvwv7a#payment-statuses-v2-flow)

PLEASE NOTE!

We recommend setting up 2 "success" statuses: finished and sending as well. Sending - means “money is on our side, and we are transferring it to your balance”.

Response fields:

- **Id** – payment ID;

- **status** – status of the transaction;

- **id** – invoice ID;

- **customerID** – ID of the customer;

- **orderID** – the value is identical to externalOrderId;

- **priceCurrency** - user's account currency: fiat or cryptocurrency (ex. USD, EUR, BTC, etc.);

- **priceAmount** - amount specified by user for a deposit/withdrawal in priceCurrency;

- **externalOrderId** - merchant's custom order ID. Example: BGBRB-30020. This ID must be unique to create a transaction;

- **sequence** - helps to differentiate between the subsequent payments. More information could be found in [multiple deposit processing](https://documenter.getpostman.com/view/17469357/UVyvwv7a#multiple-deposit-processing);

- **customerEmail** - user’s email address;

- **transactionType** - always deposit or withdrawal;

- **payCurrency** - cryptocurrency for the transaction (specified by user);

- **payAmount**:\
  - for deposits - how much the user must pay to complete a deposit;\
  - for withdrawals - the amount that will be deducted from the merchant's balance to process a withdrawal;

- **payAddress** - deposit address for crypto assets;

- **payExtra** - additional Id which is necessary for identifying a recipient of the transaction. Also known as additional address, memo or destination tag. Users must enter it while withdrawing XRP, BNB, XLM and some other currencies;

- **payHash**:\
  - for deposits - transaction hash to the deposit address;\
  - for withdrawals - transaction hash from the merchant’s balance address to an exchange address;

- **payHashLink** - link to transaction hash;

- **userNotes** - notes left by user;

- **createdAt** - time, when the transaction was created;

- **paidAmount** - amount that was actually sent in the transaction;

- **outcomeHash**:\
  - for deposits - transaction hash from an exchange address to the merchant’s balance address;\
  - for withdrawals - transaction hash from an exchange address to user’s wallet address;

- **outcomeHashLink** - link to transaction hash;

- **outcomeAmount**:\
  - for deposits - amount credited to the merchant’s wallet.\
  - for withdrawals - amount received by user in specified cryptocurrency;

- **outcomeAddress**:\
  - for deposits - merchant's crypto wallet, which is used to сollect deposits;\
  - for withdrawals - user’s address to receive the withdrawal;

- **payinSenders** - customer's wallet, used to process a deposit or merchant’s wallet to proceed a withdrawal;

- **fiat** - parameter to specify in priceCurrency. True is set by default. Pass false to create a transaction with crypto estimation, if the user's account is in crypto.

### List of payments (V2)

`GET https://api.heropayments.io/v2/payments?search`

Returns the entire list of all transactions, created with a certain API key. The list of optional parameters:

- **limit** - limits amount of transactions on a page;

- **offset** - specified to exclude a number of entries from the query;

- **status** - payment statuses: "waiting", "exchanging", "sending", "finished";

- **transactionType** - always "deposit" or "withdrawal";

- **id** - payment ID;

- **invoiceId** - invoice ID;

- **externalOrderId** - merchant's custom order ID. Example: BGBRB-30020. This ID must be unique to create a transaction;

- **customerEmail** - user’s email address;

- **customerId** - the merchant provides an ID that is associated with a particular user of the platform;

- **payAddress** - deposit address for crypto assets;

- **payCurrency** - chosen cryptocurrency for a deposit/withdrawal;

- **priceCurrency** - user's account currency: fiat or cryptocurrency;

- **dateFrom** - select the displayed period start date (date format: YYYY-MM-DD or yy-MM-ddTHH:mm:ss.SSSZ);

- **dateTo** - select the displayed period end date (date format: YYYY-MM-DD or yy-MM-ddTHH:mm:ss.SSSZ).

Additionally, there is possibility to find transactions via *"search"* parameter, where you can write in: **id, invoiceId, externalOrderId, customerEmail, payAddress, hash.**

`GET https://api.heropayments.io/v2/network-fees`

This method returns current network fees (bulk) associated with deposits and withdrawals for various cryptocurrencies.

## Deposits (API and widget)

### Create a deposit (V2)

`POST https://api.heropayments.io/v2/payments`

**Request body**

```json
{
    "payCurrency": "usdttrc20",
    "priceCurrency": "usd",
    "priceAmount": "34",
    "customerId": "123",
    "customerEmail": "test@te34st.com",
    "externalOrderId": "14545332115",
    "callbackUrl": "https://example.com/callback"
```

Use this method to create a deposit transaction. Please provide your data as a JSON-object payload.

Request fields:

- **payCurrency** (required) - cryptocurrency for the deposit (specified by user);

- **priceCurrency** (required) - the currency in user’s player account;

- **priceAmount** (required) - amount specified by user for deposit in a priceCurrency;

- **customerId** (required) - the merchant provides an ID that is associated with a particular user of the platform;

- **customerEmail** (optional) - user’s email address;

- **externalOrderId** (required) - merchant's custom order ID. Example: BGBRB-30020. This ID must be unique to create a transaction;

- **callbackUrl** (optional) - HTTP(s) URL of your server which will accept callback requests. Heropayments will send callbacks whenever the status of a transaction gets an update. If your server is inaccessible or cannot accept a callback request, our system will try to send it again until it reaches the limit of five retries;

- **fiat** - parameter to specify in priceCurrency. True is set by default. Pass false to create a transaction with crypto estimation, if the user's player account is in crypto.

Response fields:

- **id** - payment ID;

- **status** - status of the transaction;

- **id** - invoice ID;

- **customerID** - ID of the customer;

- **orderID** - the value is identical to externalOrderId;

- **priceCurrency** - user's account currency: fiat or cryptocurrency (ex. USD, EUR, BTC, etc);

- **priceAmount** - amount specified by user for the deposit in priceCurrency.

- **externalOrderId** - merchant's custom order ID. Example: BGBRB-30020. This ID must be unique to create a transaction;

- **sequence** - helps to differentiate between the subsequent payments. Please read multiple deposit processing;

- **customerEmail** - user’s email address;

- **transactionType** - always deposit or withdrawal, in this case deposit;

- **payCurrency** - cryptocurrency for the transaction (specified by user);

- **payAmount** - expected amount to pay by the user;

- **payAddress** - deposit address for crypto assets;

- **payHash** - transaction hash to the deposit address;

- **payHashLink** - link to transaction hash;

- **userNotes** - notes left by user;

- **createdAt** - time, when the transaction was created;

- **paidAmount** - amount that was actually sent in the transaction;

- **outcomeAmount** - amount credited to the merchant’s wallet;

- **outcomeCurrency** - all deposits are accumulated in the merchant's balance currency;

- **feePercent** - Heropayments processing fee;

- **feeUSDT** - Heropayments processing fee in USDT equivalent;

- **networkFee** - network fee deducted for processing the blockchain transaction;

- **priceRate** - priceCurrency to outcomeCurrency ratio;

- **payRate** - payCurrency to outcomeCurrency ratio;

- **clientAmountUsdt** - deposit amount received from a user and converted to USDT;

- **clientAmount** - fiat equivalent of clientAmountUsdt in priceCurrency. Shows the amount to be credited to users' account;

- **merchantAmountUsdt** - amount credited to Merchant’s wallet in USDT. Equals to outcomeAmount; 

- **callbackUrl** - HTTP(s) URL of your server which will accept callback requests. Heropayments will send callbacks whenever the status of a transaction gets an update. If your server is inaccessible or cannot accept a callback request, our system will try to send it again until it reaches the limit of five retries;

- **payinSenders -** the address from which the funds were originally sent (the customer’s wallet address);

- **fiat** - parameter to specify in priceCurrency. True is set by default. Pass false to create a transaction with crypto estimation, if the user's account is in crypto.

You can check the status of the payment via [GET "Payment status check by id (V2)"](https://documenter.getpostman.com/view/17469357/UVyvwv7a#f850d90d-7926-46f6-bcbf-4b90369cbbf8)

### Create an invoice (widget)

`POST https://api.heropayments.io/v2/invoices`

**Request body**

```json
{
    "priceCurrency": "usdttrc20",
    "priceAmount": "34",
    "customerId": "123",
    "externalOrderId": "64536456",
    "successUrl": "https://www.google.com/?hl=en",
    "failUrl": "https://en.wikipedia.org/wiki/Main_Page",
    "callbackUrl": "https://example.com/callback"
}
```

The customer must open the generated `invoiceUrl` to complete the deposit. On the payment widget, the customer selects the cryptocurrency to use for the payment.

Depending on the payment outcome, the customer is redirected to either `successUrl` or `failUrl`.

**Payment widget DEMO VIDEO -**\
<https://drive.google.com/file/d/1zpgT5U34Ysc7Wq83zWpinldic2yji0qc/view?usp=drive_link>

Request fields:

- **priceCurrency** (required) - the currency in user’s player account in which the priceAmount is specified and displayed on the widget;

- **priceAmount** (required) - amount specified by user for the deposit in priceCurrency;

- **customerId** (required) - the merchant provides an ID that is associated with a particular user of the platform;

- **externalOrderId** (required) - merchant's custom order ID. Example: BGBRB-30020. This ID must be unique to create a transaction;

- **successUrl** (optional) - merchant's URL after a successful payment. Also known as "thank-you page";

- **failUrl** (optional) - merchant's URL when the customer cancels the order. Also known as "cancel page";

- **callbackUrl** (optional) - HTTP(s) URL of your server which will accept callback requests. Heropayments will send callbacks whenever the status of a transaction gets an update. If your server is inaccessible or cannot accept a callback request, our system will try to send it again until it reaches the limit of five retries;

Response fields:

- **id** - invoice ID

- **customerId** - the merchant provides an ID that is associated with a particular user of the platform;

- **priceAmount** - amount specified by user for the deposit in priceCurrency;

- **priceCurrency** - user's account currency: fiat or cryptocurrency (ex. USD, EUR, BTC, etc.);

- **externalOrderId** - merchant's custom order ID. Example: BGBRB-30020. This ID must be unique to create a transaction;

- **orderDescription** - notes about the order;

- **successUrl** (optional) - redirects to Merchant's URL after successful payment. Also known as "thank-you page";

- **failUrl** (optional) - redirects to Merchant's URL when a customer cancels the order. Also known as "cancel page";

- **invoiceUrl** - Heropayments hosted URL to redirect customers to proceed the deposit;

- **callbackUrl** - HTTP(s) URL of your server which will accept callback requests. Heropayments will send callbacks whenever the status of a transaction gets an update. If your server is inaccessible or cannot accept a callback request, our system will try to send it again until it reaches the limit of five retries;

- **createdAt** - time, when the invoice was created;

- **fiat** - parameter to specify in priceCurrency. True is set by default. Pass false to create a transaction with crypto estimation, if the user's account is in crypto.

#### Create an invoice (widget) — 200 OK

## Withdrawals

### Create a withdrawal (V2)

`POST https://api.heropayments.io/v2/withdrawal`

**Request body**

```json
{
    "customerId": "123",
    "payoutAddress": "0x846CD889507F93E8E077E4813B9341ABA9fBA3B2",
    "payoutCurrency": "usdt20",
    "priceCurrency":"usd",
    "priceAmount": "3",
    "payoutExtraId": "",
    "customerEmail": "test@test.com",
    "externalOrderId": "123453356744123a",
    "callbackUrl": "https://example.com/callback"
}
```

Use this method to create a withdrawal (payout) transaction. Please provide your data as a JSON-object payload.

Request fields:

- **customerId** (required) - the merchant provides an ID that is associated with a particular user of the platform;

- **payoutAddress** (required) - your user’s address to receive the withdrawal;

- **payoutCurrency** (required) - chosen cryptocurrency for the withdrawal;

- **priceCurrency** (required) - how much will receive a user in estimated value;

- **priceAmount** (required) - amount specified by user for withdrawal in priceCurrency;

- **customerEmail** (optional) - user’s email;

- **payoutExtraId** (optional) - additional Id which is necessary for identifying a recipient of the transaction. Also known as additional address, memo or destination tag. Users must enter it while withdrawing XRP, BNB, XLM and some other currencies;

- **externalOrderId** (required) - merchant's custom order ID. Example: BGBRB-30020. This ID must be unique to create a transaction;

- **callbackUrl** (optional) - HTTP(s) URL of your server which will accept callback requests. Heropayments will send callbacks whenever the status of a transaction gets an update. If your server is inaccessible or cannot accept a callback request, our system will try to send it again until it reaches the limit of five retries;

- **fiat** - parameter to specify in priceCurrency. True is set by default. Pass false to create a transaction with crypto estimation, if the user's account is in crypto.

Response fields:

- **id** - payment ID;

- **status** - status of the transaction;

- **id** - invoice ID;

- **customerID** - ID of the customer;

- **priceCurrency** - user's account currency: fiat or cryptocurrency (ex. USD, EUR, BTC, etc.);

- **priceAmount** - amount specified by user for the deposit in priceCurrency;

- **customerEmail** - user’s email address;

- **sequence** - used for deposits only, for withdrawals remains "original";

- **externalOrderId** - merchant's custom order ID. Example: BGBRB-30020. This ID must be unique to create a transaction;

- **transactionType** - always deposit or withdrawal, in this case withdrawal;

- **payCurrency** - cryptocurrency for the transaction (specified by user);

- **payAmount** - the amount that must be deducted from the merchant's account to process a withdrawal;

- **outcomeAddress** - user’s address to receive the withdrawal’

- **payExtra** - additional Id which is necessary for identifying a recipient of the transaction. Also known as additional address, memo or destination tag. Users must enter it while withdrawing XRP, BNB, XLM and some other currencies;

- **payHash** - transaction hash from the merchant’s balance address to an exchange address;

- **createdAt** - time, when the transaction was created;

- **paidAmount** - amount that was actually sent in the transaction;

- **outcomeAmount** - the amount that a user must receive for a withdrawal;

- **outcomeCurrency** - a currency that the user chose for the withdrawal;

- **feePercent** - Heropayments processing fee (%);

- **feeUSDT** - Heropayments processing fee in the Currency equivalent;

- **networkFee** - network fee deducted for processing the blockchain transaction;

- **priceRate** - priceCurrency to outcomeCurrency ratio;

- **payRate** - payCurrency to outcomeCurrency ratio;

- **clientAmountUsdt** - USDT equivalent of a withdrawal amount sent to the user;

- **clientAmount** - equivalent of priceAmount in priceCurrency. This amount that user should receive for a withdrawal;

- **merchantAmountUsdt** - USDT amount deducted from the mechant's balance to process a withdrawal for user;

- **payinSenders** - merchant’s wallet to proceed a withdrawal;

- fiat - parameter to specify in priceCurrency. True is set by default. Pass false to create a transaction with crypto estimation, if the user's account is in crypto.

You can check the status of the payment via [GET "Payment status check by id (V2)"](https://documenter.getpostman.com/view/17469357/UVyvwv7a#f850d90d-7926-46f6-bcbf-4b90369cbbf8)

We have 2 types of daily limits:

- Merchant withdrawal limit – for the entire merchant account per day;

- Customer withdrawal limit – for each customerId per day.

To set up the limits, reach us via [partners@heropayments.io](https://mailto:partners@heropayments.io/) or contact your personal account manager.

In case of an infrastructural error, the withdrawal goes to the [withdrawal queue](https://documenter.getpostman.com/view/17469357/UVyvwv7a#abe7f3cd-0d6c-43b1-8719-ed448a0f8340), if this option is turned on for your account.
